### Staleness within one pass, and closures

- Body-time reads of @State and bindings (`compactRange`, `selectedDate`, `range`, `periodOffset`) happen once in `reading` (`new:70`). In the old code they also happened during body evaluation, just more often. Any change to these values invalidates the body and produces a new `Reading`, so nothing that mattered was being re-read mid-pass.
- Closures that run later do not touch `Reading`:
  - The range button action at `new:108-110`, the Today button at `new:91`, and the currency `Binding` setter at `new:130` only write state.
  - The `.onChange` handlers at `new:120-121` only write `selectedDate = nil`.
  - `.onAppear` at `new:122` still reads the live `history` property, exactly as at `old:108`.
  - The expanded `chartOverlay` / `CuadraoChartTouchSurface` closure (`new:213-220`) and the compact `chartGesture` closure (`new:224-231`) use only `proxy`, `geometry` and the `selectedDate` write. They are byte-identical to `old:197-215`.
- The one closure whose capture changed is the Charts `ForEach` content closure (`new:178-185`). It now captures the `bounds` let instead of calling `self.bounds` when Charts resolves the content. That capture is consistent with the `points` array the `ForEach` iterates, which in the old code was itself taken at `Chart.init`. The old closure could in principle pair a newer `bounds` with an older `points`; the new one cannot. This is not a regression. It is also the per-point rebuild that the commit removes.
- Scrubbing works as before. Every scrub frame writes `selectedDate` through `$selectedDate` (`new:223`) or the touch surface (`new:218`), which re-runs the body and produces a new `Reading`. `.sensoryFeedback(.selection, trigger: selected?.date)` at `new:123` reads the selected point from the same pass, as `old:109` did.
- Range changes and period swipes: neither this file nor its callers (`CuadraoHomeInsights.swift`, `CuadraoHomeOverview.swift`, `CuadraoChartControls.swift`, `CuadraoChartTouchSurface.swift`) contains `withAnimation` or `.animation(`. In expanded mode, `periodOffset` is `.constant(offset)` per TabView page (`CuadraoHomeInsights.swift:60`). A swipe therefore builds or reuses page views, and each page derives its own `Reading` from its own constant offset.

## 5. Other callers of the history builder (shape only, no change proposed)

- `CuadraoHomeInsights.history` (`CuadraoHomeInsights.swift:35`) is a computed property that rebuilds the history on every read. It is read through `oldest` (`:36`) twice per Insights body pass: the `ForEach(Array(oldest...0))` range at `:72` and `.onChange(of: oldest)` at `:111`. It is also read on events through `movePeriod` (`:44`) and the `metricChoice` setter (`:25`). This is the same rebuild-per-read shape, but the multiplier is a constant 2, not per point or per button.
- `balancePeriod(offset)` (`:37-39`) builds a `CanvasBalancePeriod`, which builds a history at `CuadraoBalancePeriod.swift:31` and up to two snapshots at `:40`. The distribution branch calls it twice per page (`:55` and `:56`), and up to three pages are live (`:74`, `abs(offset - periodOffset) <= 1`). That is up to 6 period builds, so 6 history builds, per Insights pass in distribution mode.
- After this commit, each expanded `CuadraoHomeBalanceChart` page builds the history twice per body pass: once at `new:45`, and once more inside `CanvasBalancePeriod.init` through `new:60`. Up to three pages are live, plus one more build per page on appear (`new:122`).
- `CanvasBalancePeriod.init` itself builds the history once per construction. The repetition comes from its callers constructing it more than once.
- Rough total for one Insights pass in balance mode: about 2 + 3 x 2 = 8 history builds. In distribution mode: about 2 + 6 = 8. At the author's 2.4 ms per build, that is about 19 ms. This estimate is unmeasured; it only says where part 2's swipe and scrub traces should look.

## Findings

- **P3** `new:33`. The doc comment says the `Reading` holds "Everything drawn from the history, derived once per body pass". In expanded mode `period` (`new:60`) builds a second history inside `CanvasBalancePeriod.init` (`CuadraoBalancePeriod.swift:31`), so the history is built twice per expanded pass, not once. Behaviour is unaffected. Smallest fix if the comment is touched again: drop "once", or leave it as is.
- **P3, evidence** LAG-phone.md says the pure function "is already covered by `DesignPreviewTests/HomeBalanceChecks.swift`". That is true of the function, but that check does not compile or exercise the changed view (`run_home_balance.py:13`). The equivalence of the view derivation rests on code reading, which this review did, and on `CuadraoHomeChartUITests`, which has not run at 20f31941. Smallest fix: the lead runs `-only-testing:ArgusFoundationUITests/CuadraoHomeChartUITests` at 20f31941 before promotion, as the author already asked.
