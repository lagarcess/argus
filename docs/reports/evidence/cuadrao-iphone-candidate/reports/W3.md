## The definition, and where

Owner: `docs/specs/lanes/account-deletion-fk-census.md`, new section "Sharing scopes and the standalone shared group" (anchor `#sharing-scopes-and-the-standalone-shared-group`), right before "Placeholders". The census bullet that used to carry the definition now links up to it.

The definition, read from `argus_private.deletion_placeholder_units` and `deletion_activity_household` in `supabase/migrations/20261004090000_account_deletion.sql` and `AccountDeletionService._units` in `src/argus/domain/account_deletion/service.py`: a standalone shared group is one activity group (`financial_activity_groups` row, for example a transfer or payment between two people's accounts) whose legs in `financial_activity_memberships` have more than one owner (the person owns it and another person's record is a leg, or another person owns it and one of the person's records is a leg), and that no household plan claims or archives (no bound `financial_plan_links`, no `household_plan_archived_claims`, no `household_plan_archived_activities` row). Its scope id is the group's own id (`scope_kind = 'group'`). It is not a household, a plan, or the founder's group access link.

## Draft issue texts (not filed)

### 1. test(db): pin credential re-sealing to its key fingerprint at the Postgres layer

Priya's final Lane 6 eval note. `secret_key_fingerprint` names the key that sealed each provider credential (`financial_source_connections`, `apple_sign_in_credentials`, `argus_private.account_deletion_revocations`), and account deletion discards an unreadable credential only when that fingerprint equals the running key's (`key_check`). The database enforces only `check (secret_ciphertext is not null or secret_key_fingerprint is null)` (`20261004090000_account_deletion.sql` L305, L1467). Nothing stops a writer from replacing the ciphertext under a new key and leaving the old fingerprint. The runbook already warns that a process on pre-Lane 6 code re-seals without updating the fingerprint.

Done when one of these holds, with a real-Postgres test: a K1 to K2 re-seal test through every sealing path (Plaid link and reconnect, Gmail connect and reconnect, Apple capture) proves the fingerprint follows the ciphertext; or a trigger nulls `secret_key_fingerprint` whenever `secret_ciphertext` changes without it, so a stale fingerprint can only read as `key_unproven` (held), never as proof. Not a flag gate today; matters before `ARGUS_ACCOUNT_DELETION_ENABLED` and any `ARGUS_INGESTION_SECRET_KEY` rotation.

### 2. test(ingestion): known-answer test for the key fingerprint derivation

Priya's note said the fingerprint derivation has no test. Partly stale: `tests/ingestion/test_secrets.py::test_key_id_names_the_key_without_revealing_it` (#799) checks that the same key gives the same id, another key another, the shape (32 hex), and that it is not the raw key. What is not pinned is the derivation itself (`SecretBox.key_id`: HMAC-SHA256 of `_KEY_ID_LABEL` under the key, truncated to 32 hex, `src/argus/domain/ingestion/secrets.py:57`). A change to the label, the hash or the truncation passes every test and silently turns every stored fingerprint into `key_unproven`, so deletions of anyone with a Plaid, Gmail or Apple token hold until an operator forces them after 7 days.

Done when a known-answer test asserts the exact fingerprint for a fixed test key, and the test names the migration step required to change it.

### 3. docs(api): OpenAPI 403 for `POST /account/delete` names placeholders, which get 401

`docs/api/openapi.yaml` (generated from `src/argus/api/routers/account.py:143`) describes `403 account_deletion_not_allowed` as "the account can't be deleted here (an account placeholder)". A placeholder never reaches that branch: its JWT is rejected by the session check and the resume check with `401` (API_CONTRACT `POST /account/delete`, "Who may call it"). The service still raises `AccountDeletionRejected("placeholder")` and `("invalid_user_id")` as a defense in depth, so 403 is reachable only in theory. Reword the description to say the account is not one the command deletes, without naming placeholders as the case clients will see, regenerate the OpenAPI artifact, and keep `tests/test_openapi_compatibility.py` green. Could fold into #803's OpenAPI item.
