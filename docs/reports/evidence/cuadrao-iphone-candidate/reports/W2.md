## Data shape (named before the views)

All in `ios/Packages/ArgusSession/Sources/ArgusSession/Invitations.swift`, mirroring `src/argus/domain/household/invite_schemas.py` and `docs/api/openapi.yaml`:

- `InviteSecret` is `.token(String)` or `.code(String)`. Exactly one is encoded, so the "exactly one of token or code" contract is unrepresentable to break. Parsing: a URL must be one of the server's two link shapes (`https://cuadrao.ai/invite#<token>`, `argus-household://invite#<token>`) or it is rejected; bare text over 32 characters (the contract's code cap) is a token; anything else is a code. The client never normalizes codes; the server folds case, dashes and look-alikes.
- `BetaAccess` (`gate_enabled, admitted, waitlist_url, testflight_url`), `InviteQuota`, `SentInvite` / `SentInvites` (state `pending|accepted|revoked|expired`, `accepted_at`), `CreatedInvite` (secrets once; `hasSecrets` false on a replay), `InvitePreview` (`beta|household|group_link`), `RedeemResult` (`admitted|already_admitted`), `GroupLink` (`open|full|expired|revoked`, `redeemed`, `overflow`).
- `InvitationProblem`: every server problem code the screens explain (`invalid, expired, revoked, used, full, rateLimited, householdInvitation, quotaExhausted, founderOnly, invitationRequired, surfaceUnavailable, signedOut, unavailable`). Mapped once at the client boundary.
- `InvitesClient` over an `InvitesTransport` protocol. Production is `SessionInvitesTransport` (the existing `SessionController.financialRequest`, bearer, same-origin, `Idempotency-Key` only on creates).

The three facts stay separate:
- Beta admission: `InvitationsModel.admission` (`checking | surfaceOff | unknown | admitted | required`), always re-read from `GET /invites/access`. A redeem or a Household accept never sets it directly; the model re-reads access afterwards.
- Household membership: unchanged owner `HouseholdModel` (`households`, `selectedId`). A Household code or link is handed to its join step; nothing in the invitations model reads or writes membership.
- Financial account access: unchanged (`HouseholdShare` / grants in `HouseholdManagement`). Nothing here touches it, and the copy says an invitation does not share accounts.
