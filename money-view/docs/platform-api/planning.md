# Planning API

All routes require household session context. GET permitted to viewer; mutations require editor/owner. Money is decimal strings, currencies are separate. All records include dated source evidence. Prefix `/api/platform`.

- `GET /budgets?month=2026-09` → `{items:[{id,category,currency,month,limit,actual,remaining,evidence}]}`. `POST /budgets`, `PUT /budgets/{id}` body `{"category":"groceries","currency":"USD","month":"2026-09","limit":"800"}`; `DELETE /budgets/{id}`.
- `GET /budgets/{id}` → one budget with the same canonical ledger projection and evidence as the list, using its saved month and currency. Viewer reads allowed. Foreign, missing, and archived records return `404 planning_record_not_found`. Receipt navigation supplies only `record_id`; the frontend derives the displayed month from this response.
- `GET /bills` → `{items:[{id,name,account_id,category,currency,amount,cadence,anchor_date,next_due,status,evidence}]}`. `POST /bills`, `PUT /bills/{id}` body `{"name":"Utilities","account_id":"<ledger account>","category":"utilities","currency":"USD","amount":"90","cadence":"monthly","anchor_date":"2026-09-30"}`. Cadence: weekly/monthly/quarterly/yearly. `POST /bills/{id}/pause` body `{"paused":true}`; `POST /bills/{id}/skip`; `POST /bills/{id}/pay` body `{"due_date":"2026-09-30"}` records a **local** ledger transaction once per occurrence. `DELETE /bills/{id}` archives schedule.
- `GET /goals` → `{items:[{id,name,target_date,target_amount,monthly_contribution,currency,status,allocations:[{account_id,amount}],allocated,remaining,evidence}]}`. `POST /goals`, `PUT /goals/{id}` body `{"name":"Emergency reserve","target_date":"2028-01-01","target_amount":"10000","monthly_contribution":"250","currency":"USD"}`; `PUT /goals/{id}/allocations` body `{"allocations":[{"account_id":"<ledger account>","amount":"1500"}]}`. Allocations reserve live balance across active goals; no currency mixing or overbooking. `DELETE /goals/{id}` archives.
- `GET /scenarios/templates` → `{items:[{id,inputs}]}`; ids home/kids/job/move/marriage/retirement/sabbatical. Every template uses the same calculator.
- `POST /scenarios/calculate` body below → calculation (no save).
- `POST /scenarios` body below → immutable `{id,name,template,inputs,result,evidence}`. `GET /scenarios?limit=20&offset=0` → `{items:[summary],total,limit,offset}`. The list is ordered newest first, defaults to 20 rows, and permits 1–100 rows per page; offset is nonnegative. Each summary retains `id,name,template,inputs,evidence,result`, but `result` omits `months` and `years`. Show the total and page controls; fetch the selected receipt for detailed series. `GET /scenarios/{id}` returns one receipt. `GET /scenarios/compare?before_id=...&after_id=...` → `{before,after,delta_ending_balance}`; currency must agree. There is no receipt edit endpoint: save a new version to compare.

```json
{"name":"Retirement baseline","template":"retirement","inputs":{"currency":"USD","initial_balance":"100000","monthly_contribution":"500","monthly_withdrawal":"0","horizon_years":20,"annual_return_pct":"4","inflation_pct":"2","annual_fee_pct":"0.5","contribution_start_month":1,"contribution_end_month":120,"withdrawal_start_month":121,"withdrawal_end_month":240,"timing":"end"}}
```

Calculator output: `{currency,ending_balance,real_ending_balance,total_contributions,total_withdrawals,total_fees,depletion_month,months:[{month,balance,real_balance,contribution,withdrawal,unfunded_withdrawal,fee}],years:[{year,balance,real_balance}],method}`. Annual return and inflation are effective rates converted to monthly; annual fees charged monthly as annual_fee_pct/12; cash-flow timing begin/end explicit; balances floor at zero and unmet withdrawal remains visible. Results are illustrative assumptions, not promises. Inputs bounded to 100 years, money 1e12, annual rates [-99,100], fees [0,20]. Initial/contribution/withdrawal nonnegative. 

Public Python: initialize(store), list_budgets(store,context,month=None), list_goals(store,context), list_bills(store,context), list_scenarios(store,context,limit=20,offset=0), calculate_scenario(inputs). Write helpers documented in source. All operate through Store.connection and PlatformError.

Calculation responses also include `evidence` next to calculation fields. Budget list `evidence` is calculated provenance over the saved limit and current ledger summary; `input_evidence` preserves the recorded budget source and `actual_evidence` preserves the ledger source (including synthetic status). Goal allocation rows additionally carry `account_balance`, `account_evidence`, `account_unavailable`, and `underfunded`. Existing reservations stay visible when later spending reduces backing balances; new allocations fail if total reserved exceeds current balance. An archived/deleted account is marked unavailable, never silently treated as valid backing.

Lifecycle integration: `export_data(connection, context)` returns owned rows, `clear_data(connection, context)` removes household planning state, and `usage_data(connection, context)` counts plans/scenarios. Clear preserves the initialization manifest so a deleted/reset household stays empty after restart. Call planning.initialize after ledger.initialize to seed a DOP demo bill against its real fixture account.

Budget and bill categories must map to `expense` in the canonical ledger category catalog. Income and transfer categories are rejected at input validation.
